codediff.nvim                                 *codediff.txt* *codediff.nvim* *codediff*

This fork provides Git review, staging, revision comparisons, history, and
conflict resolution in Neovim.

REQUIREMENTS                                            *codediff-requirements*

Use Neovim 0.10 or newer: this fork uses vim.system(), vim.fs APIs, and floating
window footers. The old Neovim 0.7 compatibility claim does not apply to these
workflows. Git is required for repository operations. See README.md for the
native diff library, installation, and build requirements.

With lazy.nvim's command/key loading, the manual is available only after the
plugin loads. Run :Lazy load codediff.nvim, then :help codediff to read it
without opening a review. :CodeDiff help loads the plugin and opens its
shortcut popup directly.

==============================================================================
FIRST REVIEW TO COMMIT                                    *codediff-quickstart*

1. Save the files you want to review in the ordinary editor. Open a file in
   your repository, then run:
>vim
     :CodeDiff
<
   To choose a different repository, use |codediff-repo|.
2. In Unstaged, move with i/k; expand a folder with l and press Enter on a
   file. Before shows the index; After shows your working file.
3. Press Tab until a diff pane has focus. Move onto a changed block with ].
   Check the > markers and Hunk N/M footer before acting.
4. Press s in that diff pane to stage only that hunk. To stage a whole file
   or folder instead, focus its tree row and press s there.
5. Focus Staged and select the file to inspect what will be committed.
   Pressing s on a staged hunk unstages it without removing working edits.
6. Press c, read the branch/HEAD shown in the title, and type a commit message.
   Ctrl-s commits the existing index only; it does not stage remaining edits.
   Ctrl-q cancels the message dialog. See |codediff-repository|.
7. Press q in the workspace to return to your original editor.

To throw away working-file changes, read |codediff-revert| first. Unstage and
Revert are different operations; Revert is not an alternative spelling of
Unstage.

REVIEW WORKSPACE                                             *codediff-popup*

With the default side-by-side layout, :CodeDiff opens a popup in the current
tab, even when the repository is clean:
>
  +-------------+----------------------+----------------------+
  | Unstaged    | Before               | After                |
  |             |                      |                      |
  +-------------+                      |                      |
  | Staged      |                      |                      |
  |             |                      |                      |
  +-------------+----------------------+----------------------+
<
The left column is deliberately narrow; the two numbered diff panes take most
of the width. Selecting a conflict uses the four-pane merge grid in
|codediff-merge| instead. Review hides the editor statusline and mode area;
the merge popup restores your command-line height for ordinary editing.

Default initial focus is the explorer (configurable with explorer.initial_focus).
Selecting a file in a popup tree does not jump focus into its diff. Tab cycles
Unstaged -> Staged -> Before -> After, then wraps. In a merge the code panes
instead cycle Incoming -> Current -> Base -> Result.
Shift-Tab reverses the order. The tree row chooses the file; the cursor in a
diff pane chooses the hunk. Closing a child dialog returns to its source pane.

Explicit revisions, history, --staged, file/directory comparisons, and --inline
use native tabs instead: |codediff-native|. Setting diff.layout = "inline"
also opts out of the status popup. Ordinary popup geometry and navigation are
fixed. The merge popup uses explorer.width where space permits and the merge
keymaps in |codediff-merge|, not the ordinary review key layer.

POPUP SHORTCUTS                                         *codediff-popup-keys*

These are Normal-mode keys for ordinary status review, not merge panes or
ordinary Vim editing. Merge Result uses normal editing: |codediff-merge|.
Editable dialogs have their own submission keys.

  Scope        Key                  Action
  Workspace    q / Ctrl-q           Close review, restore editor
               Tab / Shift-Tab      Next / previous pane
               i / k                Move up / down
               h                    Help
               Ctrl-s / Ctrl-Shift-s Help, NOT save
               c                    Commit dialog
               z                    Confirm tracked-only stash
               b / w                Local branch / worktree lists
  Trees        Up / Down            Move up / down
               j / l                Collapse / expand folder; l selects file
               Enter / double-click Select file or toggle folder
               s                    Stage/unstage file or folder
               S / U                Stage / unstage all files
  Diff panes   j / l                Move left / right
               [ / ]                Previous / next hunk
               s                    Stage/unstage cursor's hunk
               r                    Confirm working-file Revert

:CodeDiff help also opens shortcuts outside review; in a native session it
shows that session's configured mappings. Native gS/g?/t and keymaps.view or
keymaps.explorer settings do not replace ordinary review's fixed popup layer.
Merge panes are the exception: use g? and |codediff-merge|.

HUNK SELECTION                                               *codediff-hunks*

A hunk is a contiguous changed block computed by the diff engine. Place the
cursor inside it in Before or After, or jump with [ / ]. The selected hunk has
> gutter markers, emphasized line numbers on both sides, and a Hunk N/M footer.
Hunk -/M means no hunk is selected. On a deletion-only side, its boundary line
is the selection point.

Selection means the cursor's whole hunk, not a Visual selection or an arbitrary
set of highlighted lines. Popup s and r act on that hunk. A tree row is not a
hunk selection. If a refresh changes the comparison, select the hunk again.

==============================================================================
STAGE AND UNSTAGE                                          *codediff-staging*

Git has three relevant states: HEAD (last commit), index (next commit), and
worktree (files on disk).

Stage copies selected working changes into the index. Unstage removes selected
changes from the index while keeping the working file intact. Neither commits.
In popup diffs, s stages from Unstaged and unstages from Staged. In trees it
acts on the selected file/folder instead. A folder action targets its whole
directory path, including changes hidden by presentation filters; S/U operate
on the entire repository. Inspect Staged before committing after broad actions.

File/folder staging reads disk; hunk staging can use unsaved buffer text without
writing the file. Save first if the file, preview, and index should agree.
Merge files require explicit resolution and a saved Result before whole-file
staging. Hunk actions do not apply to the merge grid: |codediff-merge|.

REVERT WORKING-FILE HUNK                                    *codediff-revert*

Popup r (diff panes only) restores the selected working-file hunk to the
Before/original comparison baseline. Native tabs use the configured
keymaps.view.revert_hunk, default <leader>hr. A native layout may reposition
the original pane; Revert still uses its version, not a physical screen side.

  Comparison                 Original         After       Revert target
  Unstaged                   Index            Worktree    Index
  Staged                     HEAD             Index       HEAD
  Revision vs worktree       Given revision   Worktree    Given revision
  --staged <revision>         Given revision   Index       Given revision
  Two immutable revisions    First revision   Second rev  Not available
  Merge/conflict             Merge sides      Result      Not available

An absent original file is an empty baseline. The action writes the working
file even when After displays the index. It NEVER changes the index. Thus
reverting a staged hunk leaves that content staged and eligible for commit;
the working file may now contain an opposite, unstaged change. To remove the
change from the next commit too, unstage it separately.

Example: stage a hunk, inspect it in Staged, then use r and confirm. Its working
content returns to HEAD, but the Staged entry remains. Press s on that staged
hunk to remove it from the index as well.

Popup confirmations use y to accept; n, q, Esc, or Ctrl-q cancel. Native tabs
use Neovim's Revert/Cancel prompt. Revert preserves unrelated hunks and the
file's CRLF/no-final-newline state. It refuses stale comparisons, changed
index/worktree state, unsaved affected buffers, renamed comparisons, or
overlapping working edits it cannot safely match. Save in the editor and
refresh/reselect rather than forcing a refused action.

WARNING: discarded unstaged content may not be recoverable by Git.

==============================================================================
REPOSITORY ACTIONS                                     *codediff-repository*

These actions require the Git status popup and affect its repository, not just
the selected file. They are not branch/worktree management or stash browsing.

Commit (c)~
The editable dialog starts in Insert mode. Its title shows the current branch
and short HEAD object ID; detached and unborn HEAD are supported. Type the
message, then Ctrl-s in Insert or Normal mode to commit only the current index.
Normal-mode s also submits. Nothing is automatically staged or saved.

An empty message, empty index, or HEAD change blocks submission. Git and hook
errors keep the message for correction/retry while the dialog stays open. If
HEAD changed, copy any needed message, cancel, and reopen the dialog. Ctrl-q
cancels from Insert or Normal mode; cancelling/closing discards this scratch
message. These drafts are not persistent commit-message storage.

Stash (z)~
Confirm with y to run a tracked-only stash: staged and unstaged tracked changes
are saved, then index and tracked working files reset to HEAD. Untracked files
remain in place. An unborn HEAD or changed HEAD blocks the operation.

Unsaved tracked buffers block stash, including buffers for staged deletions.
Clean affected buffers reload safely afterward; if a buffer becomes modified
while Git runs, its unsaved edits are retained and a warning is shown. Read any
reload error: Git may have succeeded even if an editor buffer could not reload.
There is no stash picker, pop, or apply action; use Git outside this UI.

Read-only lists (b / w)~
b lists LOCAL branches with current-branch marker, short object ID, and subject.
w separately lists worktree paths, branch/HEAD information, and available
detached/bare/locked/prunable flags. Use i/k to move; q, Esc, or Ctrl-q closes.
Neither list switches, creates, or deletes branches/worktrees.

==============================================================================
SAFETY AND RETURN TO EDITING                                *codediff-safety*

Close the status popup to restore the underlying window/view, editor chrome,
and ordinary mappings. Switching files or closing review must not abandon
unsaved user buffers. No review shortcut is a universal file-save key.

In the author's personal configuration, Space d opens review and s saves only
outside review. These are not plugin defaults. In review, use
|codediff-popup-keys|; in the commit dialog Ctrl-s means Commit, never write the
source file. Save source changes in the ordinary editor before retrying a
refused destructive action.

That personal configuration also suspends trailing-blank-line normalization
for ALL CodeDiff sessions, including native tabs, and resumes it for ordinary
editing. This is a user autocmd policy, not a CodeDiff formatting feature.

==============================================================================
NATIVE COMPARISON TABS                                      *codediff-native*

Revision comparisons, history, PRs, file/directory comparisons, --staged, and
inline layouts keep native full-tab views and configured keymaps. Do not apply
popup movement/save/repository-action keys to them. Merge conflicts always use
the fixed grid and controls in |codediff-merge|, even from an inline view.

Defaults include ]c/[c for hunks, ]f/[f for files in explorer/history, g? for
help, t for layout, and q to close the diff tab. Native explorer gS switches
the selected file between staged/unstaged views when applicable; - toggles
file staging. Diff buffers use <leader>hs to stage a hunk, <leader>hu to unstage,
and <leader>hr to Revert (subject to |codediff-revert|). Use :CodeDiff help to
see active configured keys.

Ordinary immutable revision buffers are read-only. Working-file panes are real
buffers; do not assume every comparison pane is immutable. Native do/dp
diff-get/put and conflict acceptance are separate buffer-editing operations,
not substitutes for the confirmed, index-preserving Revert action.

==============================================================================
USAGE                                                       *codediff-usage*

Status review (same-tab popup with the default layout):
>vim
  :CodeDiff
<

Native revision explorers (new tabs):
>vim
  :CodeDiff HEAD~5
  :CodeDiff main
  :CodeDiff abc123
  :CodeDiff main HEAD
<
One revision compares that baseline with the working tree; two revisions
compare immutable Git content. Neither form checks out the revision.

Explicit layout for this invocation:
>vim
  :CodeDiff --inline
  :CodeDiff --side-by-side main HEAD
<
--inline uses a native tab, including for status. --side-by-side without
revisions uses the status popup. See |codediff-native| for key scope.


Target another repository (explorer and history modes):   *codediff-repo*
>vim
  :CodeDiff --repo ~/code/other-repo
  :CodeDiff --repo ~/code/other-repo main
  :CodeDiff -C ~/code/other-repo history
<
Operate on the repository containing the given path (its root or any
subdirectory) instead of the current buffer/cwd. `-C` is a git-style alias.

Review a pull request without checking it out:                 *codediff-pr*
>vim
  :CodeDiff pr 512
  :CodeDiff --repo ~/code/other-repo pr 512
  :CodeDiff pr 512 --remote upstream
  :CodeDiff pr 512 --base release/3.x
  :CodeDiff pr 512 -- lua/codediff
<
CodeDiff recognizes GitHub and Azure DevOps `refs/pull/` refs and GitLab
`refs/merge-requests/` refs. It prefers a synthetic merge ref, which identifies
both sides of the review. Otherwise it compares the PR head with the remote's
default branch; use --base for a non-default target. `origin` is the default
remote. Existing Git remote authentication is used; no provider CLI is needed.

Fetched refs live under `refs/codediff/pull-requests/`, are overwritten when the
same PR is reopened, and do not create a local branch or change the working
tree. They are retained for asynchronous file loading and reuse.

Delete cached refs explicitly:                              *codediff-pr-clean*
>vim
  :CodeDiff pr clean 512
  :CodeDiff pr clean 512 --remote upstream
  :CodeDiff pr clean --all
  :CodeDiff pr clean --all --remote upstream
<
The first form deletes every cached ref for one PR on `origin` unless --remote
is supplied. --all deletes every cached PR ref in the selected repository;
--remote limits it to one remote. Both forms support --repo/-C.

Scope to a subdirectory or path:                          *codediff-pathspec*
>vim
  :CodeDiff v1.0.1 v1.0.2 -- modules/network
  :CodeDiff -- src/api
  :CodeDiff main... -- packages/ui
<
Append `-- <path>` to narrow the explorer file list to a subtree, like
`git diff <rev> <rev> -- <path>`. Paths are git pathspecs relative to the
repository root; multiple paths and git glob syntax are supported. Composes
with merge-base (`...`) and --repo/-C.

Show only staged changes:                                  *codediff-staged*
>vim
  :CodeDiff --staged           " index vs HEAD (--cached is an alias)
  :CodeDiff --staged HEAD~3    " index vs another revision
<
These open native tabs. In a native status explorer (for example,
:CodeDiff --inline), gS (keymaps.view.toggle_staged_view) switches the current
file's staged/unstaged view. The popup instead has separate trees; see
|codediff-popup|.

Git diff mode (current buffer vs revision):
>vim
  :CodeDiff file HEAD
  :CodeDiff file HEAD~1
  :CodeDiff file abc123
  :CodeDiff file main
  :CodeDiff file v1.0.0
  :CodeDiff file main HEAD
<

Requirements:
- Current buffer must be saved to a file
- File must be in a git repository
- Git revision must exist

Behavior:
- One revision: original Git content against the working-file buffer
- Two revisions: immutable Git content on both sides
- Opens in a new native tab with asynchronous Git loading
- See |codediff-native| for keymaps and working-buffer safety

File comparison mode:
>vim
  :CodeDiff file file_a.txt file_b.txt
<

Directory comparison mode:
>vim
  :CodeDiff ~/project-v1 ~/project-v2
  :CodeDiff dir /path/to/dir1 /path/to/dir2
<

Shows files as Added (A), Deleted (D), or Modified (M) based on file size and
modification time. Select a file to view its diff.

File history mode:                                    *codediff-history*
>vim
  :CodeDiff history
  :CodeDiff history HEAD~10
  :CodeDiff history origin/main..HEAD
  :CodeDiff history HEAD~20 %
  :CodeDiff history --reverse
<

Line-range history (visual selection):            *codediff-history-line-range*

Visually select lines and run `:CodeDiff history` to show only commits that
modified the selected line range. Uses `git log -L` under the hood.
>vim
  :'<,'>CodeDiff history
  :'<,'>CodeDiff history HEAD~10
  :'<,'>CodeDiff history --reverse
<

Each commit is compared against its parent by default. Use --base to compare
every commit against a fixed reference instead:
>vim
  :CodeDiff history --base WORKING
  :CodeDiff history --base HEAD
  :CodeDiff history --base main
  :CodeDiff history HEAD~10 -b WORKING %
<

Options:
  --reverse, -r   Show commits oldest first
  --base, -b      Compare each commit against a fixed revision instead of
                  its parent. Accepts any git revision (HEAD, branch name,
                  commit hash) or WORKING for the current working tree.

Merge conflicts:                                           *codediff-merge*
>vim
  :CodeDiff merge path/to/file
<
Or select an entry under Merge Changes in status. The file tree stays left;
Incoming (:3) and Current (:2) sit above Base (:1) and Result in a fixed 2x2
grid. The three sources are read-only. Result is the editable working file.
Git stages determine the roles, not focus or diff.original_position. During a
rebase, ours/theirs may differ from your usual branch perspective.

For a fresh Git conflict, Result combines non-conflicting and identical changes;
unresolved regions contain Base text with visible markers/counts. Existing
Result edits survive file switches and reopening, so a previously edited file
may retain conflict markers rather than being regenerated. Approvals survive
only while its buffer remains loaded, not buffer deletion or Neovim restarts.

Conflict defaults below use keymaps.conflict. Shared quit/help/file navigation
and tree focus/visibility use keymaps.view; Tab, Shift-Tab, and CTRL-Q are fixed.
  ]x / [x          Next / previous unresolved conflict; align every pane
  <leader>ct / <leader>co  Take Incoming / Current
  <leader>cb / <leader>cR  Both: Current then Incoming / Incoming then Current
  <leader>ca       Use Base and mark resolved
  <leader>cm       Mark a manual resolution resolved
  <leader>cx       Reset to Base and mark unresolved
  <leader>cT / <leader>cO  Take Incoming / Current for all unresolved conflicts
  <leader>cB / <leader>cX  Both (Current then Incoming) for unresolved / reset all
  u / CTRL-R      Undo / redo Result content and approvals
  <leader>cs       Toggle linked vertical scrolling (default on)
  <leader>cz       Maximize / restore focused pane
Result also accepts 2do / 3do for Incoming / Current. Horizontal scrolling
remains independent. Tab / Shift-Tab cycle panes; <leader>b / <leader>e hide /
focus the tree. ]f / [f select the next / previous listed file; gf opens the
focused file in the previous tab. Use g? or :CodeDiff help for shortcuts and
q / CTRL-Q to close.

Result uses ordinary Neovim editing even inside the popup: i inserts, h/j/k/l
move normally, and s is not staging. Popup trees retain their fixed controls,
including s to stage and h for help. Manual edits do not resolve conflicts:
use Mark Resolved. Editing an approved block invalidates approval. Use Base
resolves; Reset does not. Per-block choices can replace an earlier choice;
Take All skips approved blocks. Reset All resets every block while keeping
automatic non-conflicting edits. Both retains complete alternatives in order.

Write Result with :write, then stage the whole file with - (or s in a popup
tree). CodeDiff refuses file/folder/all staging for affected unopened,
unresolved, unsaved, or stale-input conflicts. Hunk operations cannot bypass
this guard. External git add does bypass it. Finish the Git operation yourself.
Tree rows show unresolved counts or "needs review" for unknown/stale inputs.
Close offers Discard, Cancel, or Keep changes and close for unsaved Results.
Discard reloads the last disk contents, not the pre-merge file; Keep retains
buffers and undo history. If preserved edits make a range ambiguous, automatic
replacement is refused: edit Result manually and Mark Resolved.
Binary/delete/unsupported rename, symlink/submodule, and differing file-mode
conflicts must be handled outside CodeDiff. Text add/add uses an empty Base.

Git merge tool (POSIX-shell quoting):
>sh
  git config --global merge.tool codediff
  git config --global mergetool.codediff.cmd 'nvim "$MERGED" -c "CodeDiff --exit-on-close merge \"$MERGED\""'
<
With --exit-on-close, resolve and :write, then use CodeDiff's q / CTRL-Q.
Its close action checks unresolved/unsaved, changed-input, and changed-on-disk
state. :cquit aborts with a failing status; direct/forced Neovim quits bypass
CodeDiff's checks. Git may ask you to confirm success and stages successful
resolutions itself. CodeDiff does not commit or continue a merge automatically.

The old diff.conflict_ours_position and diff.conflict_result_* layout settings
are removed; role meanings no longer depend on positions.

CONFIGURATION                                        *codediff-configuration*

The configuration below covers native layouts, merge actions, and rendering.
Ordinary status review has fixed pane geometry and |codediff-popup-keys|; native
explorer sizing/keymaps do not remap that layer. The merge popup respects
explorer.width where space permits, with |codediff-merge| controls. Rendering
options still apply where supported. diff.layout = "inline" selects native
status tabs, but conflicts always use the fixed merge grid.

                                                      *codediff-layout*
Diff layout~

CodeDiff supports two diff layouts:

  `"side-by-side"` (default): Two panes with synchronized scrolling.
  `"inline"`: Single pane with deleted lines shown as virtual overlays.
              Includes treesitter syntax highlighting on virtual lines.

Set the layout in your config:
>lua
  require("codediff").setup({
    diff = { layout = "inline" },
  })
<
Merge roles are fixed; diff.original_position does not swap them.

                                                      *codediff-filler-text*
Filler appearance~

Alignment rows keep corresponding content at the same vertical position in
side-by-side and conflict views. By default, these rows use a repeated
slash pattern. Set a different text pattern or use an empty string to keep
the alignment rows blank:
>lua
  require("codediff").setup({
    diff = { filler_text = "· " },
  })

  require("codediff").setup({
    diff = { filler_text = "" },
  })
<

Non-empty patterns use the CodeDiffFiller highlight group. Inline deleted
lines and move annotations are not filler rows and are unaffected.

                                                      *codediff-moved-code*
Moved code detection~

CodeDiff can detect blocks of code that moved within a file, similar to
VSCode's experimental `diffEditor.experimental.showMoves` feature.

Enable in your config:
>lua
  require("codediff").setup({
    diff = { compute_moves = true },
  })
<

When enabled:
- Moved lines get a distinct background highlight (CodeDiffLineMove)
- Sign column shows box-drawing characters (┌│└) marking the moved block
- Annotation lines (⇄ moved: L3-8 → L11-16) appear above each moved block
- In native side-by-side tabs, press gm to align a moved block with its pair

The native gm keymap disables scrollbind and positions both panes so the moved
block appears at the same visual row. Moving the cursor outside the block
or switching windows restores normal scrollbind.

TOGGLING LAYOUT                                   *codediff-toggle-layout*

Press t in an ordinary native diff tab to toggle side-by-side and inline layout.
The current file is re-rendered in explorer, history, and standalone views.
Layout toggling, compact mode, and move alignment are unavailable in merge
grids; t is also not installed in ordinary status popups.

The toggle keymap can be customized:
>lua
  require("codediff").setup({
    keymaps = {
      view = {
        toggle_layout = "t",  -- or false to disable
      },

EXPLORER LINE STATISTICS                  *codediff-explorer-line-statistics*

Explorer line statistics are disabled by default because they require extra Git
queries and consume space in the default 40-column Explorer. With `enabled =
true`, tracked files show Git numstat counts and group headings show totals in
status, one-revision, and two-revision modes. Untracked files have no stats
unless `count_untracked = true`; files larger than `max_untracked_bytes` are not
read (1 MiB by default).

Files use `+12 -4` (`bin` for binary files); group headings use `Changes (3 ·
+42 -8)`. Aggregate folder and group stats contain `files_changed`,
`insertions`, `deletions`, `binary_files`, and `unavailable_files`.

EXPLORER LINE FORMATTERS                    *codediff-explorer-line-formatters*

`explorer.formatters.file`, `folder`, and `group` replace the complete
corresponding explorer row. Each callback receives row metadata and returns a
layout:
>lua
  {
    left = {
      {
        segments = { { text = "name.lua", hl = "Normal" } },
        truncate_priority = 2,
      },
    },
    right = {
      {
        segments = { { text = "M", hl = "CodeDiffStatusModified" } },
      },
    },
    min_gap = 2,
  }
<

A region contains styled `segments`. A numeric `truncate_priority` makes it
truncatable; lower priorities truncate first. Regions without one stay fixed
unless all content cannot fit. The renderer measures display cells, truncates
with `explorer.ellipsis` (default `…`), right-aligns `right`, and preserves
`min_gap` when space permits. The built-in file formatter truncates the
directory, filename, then stats while keeping status fixed. The ellipsis can
contain multiple characters and is clipped display-width-aware when necessary.

Each segment is `{ text = string, hl? = highlight }`. `hl` accepts a Neovim
highlight group, a `#RGB`/`#RRGGBB` foreground color, or a highlight definition
such as `{ fg = "#3fb950", bold = true }`. Omitted highlights use `Normal`;
selected file rows retain their selection background.

File contexts contain `path`, `filename`, `directory`, `old_path`, `group`,
`stats`, `status`, `status_hl`, `status_right_margin`, `indent`, `indent_hl`,
`icon`, and `icon_hl`.
Conflict rows also expose `conflict = { reviewed, unresolved_count }`; the count
is nil until the current inputs have been reviewed, not an implicit zero.

Folder contexts contain `name`, `path`, `group`, `file_count`, `stats`, `files`,
`indent`, `indent_hl`, `icon`, `icon_hl`, and `expanded`. Group contexts contain
`name`, `label`, `file_count`, `stats`, `files`, and `expanded`. `stats` is nil
when line statistics are disabled.

Folder and group `files` contain `{ path, old_path, group, status, stats }`
entries for every represented file. Built-in callbacks are exported by
`codediff.ui.explorer.formatters` and return fresh layouts that can be assigned
directly or wrapped.

Example: replace only group rows and right-align the file count:
>lua
  require("codediff").setup({
    explorer = {
      formatters = {
        group = function(ctx)
          return {
            left = {{
              segments = {{
                text = " " .. ctx.label,
                hl = "CodeDiffExplorerTreeGroup",
              }},
              truncate_priority = 1,
            }},
            right = {{
              segments = {{
                text = ctx.file_count .. " files",
                hl = "Number",
              }},
            }},
          }
        end,
      },
    },
  })
<

GUTTER SIGNS                                         *codediff-gutter-signs*

Gutter signs are disabled by default and require Neovim 0.10+, because a sign
extmark spanning several lines only decorates every line from 0.10 on. When
enabled, they appear in every window displaying a buffer used by an active
CodeDiff view. CodeDiff removes them when the view is suspended or closed.

>lua
  -- Disabled by default; existing move annotations remain.
  gutter_signs = false

  -- Enabled defaults.
  gutter_signs = {
    insert_text = "＋",
    delete_text = "－",
    highlight_numbers = true,
    changed_priority = 100,
    unchanged_priority = nil,
  }

  -- Hide other Neovim signs with lower priorities.
  gutter_signs = {
    changed_priority = 100,
    unchanged_priority = 7,
  }
<

Place `gutter_signs` under `diff`. `insert_text` and `delete_text` must each
occupy one or two display cells, as measured by strdisplaywidth(), because
Neovim limits sign text to two display cells. The fullwidth defaults each
occupy two display cells. A rejected sign is skipped with a warning and the
rest of the diff still renders.

The optional +/- gutter-sign feature does not modify signcolumn/statuscolumn.
The popup separately supplies numbered panes and active-hunk > markers
(|codediff-hunks|). For native tabs, this example keeps a sign column and places
signs after line numbers:

>lua
  vim.opt.signcolumn = "yes"
  vim.opt.statuscolumn = "%C%=%l %s"
<

`signcolumn = "yes:2"` allows a second sign on each line. Changed signs use
priority 100 by default. An unchanged blocker at priority 99 can hide
lower-priority Gitsigns, remote signs, diagnostics, debugger signs, and other
signs across unchanged lines while changed signs still win.

HIGHLIGHT GROUPS                                     *codediff-highlight-groups*

CodeDiff defines highlight groups matching VSCode's diff colors:
- CodeDiffLineInsert - light green background for inserted lines
- CodeDiffLineDelete - light red background for deleted lines
- CodeDiffCharInsert - deep/dark green for inserted characters
- CodeDiffCharDelete - deep/dark red for deleted characters
- CodeDiffFiller - gray foreground for non-empty filler line patterns
- CodeDiffLineMove - background for moved lines (derived from DiffChange)
- CodeDiffCharMove - character-level highlight for moved text
- CodeDiffMoveFrom - sign/annotation color for move source
- CodeDiffMoveTo - sign/annotation color for move destination
- CodeDiffHelpSection - section headings in keymap help (links to Statement)
- CodeDiffHelpKey - key bindings in keymap help (links to Special)
- CodeDiffHelpSep - separators in keymap help (links to NonText)
- CodeDiffHelpDesc - descriptions in keymap help (links to Normal)
- CodeDiffGutterInsert - Gutter insert sign (defaults to CodeDiffLineInsert)
- CodeDiffGutterDelete - Gutter delete sign (defaults to CodeDiffLineDelete)
- CodeDiffGutterInsertNumber - Gutter insert line number (defaults to CodeDiffCharInsert)
- CodeDiffGutterDeleteNumber - Gutter delete line number (defaults to CodeDiffCharDelete)
- CodeDiffActiveHunk - selected popup hunk line numbers (bold and underlined)
- CodeDiffActiveHunkSign - selected popup hunk > markers (links to DiagnosticWarn)

Default behavior:
- Uses DiffAdd and DiffDelete for line-level highlights
- Full-file highlighting for added, untracked, and deleted files is disabled by default
- Set diff.highlight_added_deleted_files = true to enable it with line_insert and line_delete
- Character-level highlights auto-adjusted based on vim.o.background:
  - Dark themes: brightness multiplied by 1.4
  - Light themes: brightness multiplied by 0.92

  highlights = {

    char_brightness = 1.5,

    line_delete = "DiffDelete",
    char_insert = "#3fb950",
    char_delete = "#ff7b72",

USER AUTOCMD EVENTS                                     *codediff-events*

CodeDiff emits User autocmd events at key lifecycle points:

*CodeDiffOpen*    Fired after the diff view is fully ready.
*CodeDiffClose*   Fired before cleanup starts.
*CodeDiffFileSelect*  Fired when a file is selected in explorer.

All events pass a `data` table accessible via the autocmd callback's
`args.data` field:

  CodeDiffOpen / CodeDiffClose:
    `tabpage`   Tab page ID of the diff session.
    `mode`      One of "explorer", "standalone", or "history".

  CodeDiffFileSelect:
    `tabpage`   Tab page ID of the diff session.
    `path`      Relative file path selected.
    `status`    Git status code (e.g., "M", "A", "D").

Example: Hide tabline while CodeDiff is open:
>lua
  vim.api.nvim_create_autocmd("User", {
    pattern = "CodeDiffOpen",
    callback = function()
      vim.g.codediff_saved_showtabline = vim.o.showtabline
      vim.o.showtabline = 0
    end,
  })
  vim.api.nvim_create_autocmd("User", {
    pattern = "CodeDiffClose",
    callback = function()
      if vim.g.codediff_saved_showtabline then
        vim.o.showtabline = vim.g.codediff_saved_showtabline
        vim.g.codediff_saved_showtabline = nil
      end
    end,
  })

MIGRATION                                                *codediff-migration*

- Older "reject"/"discard hunk" wording is now Revert: restore the working-file
  hunk to the comparison's original baseline, leaving the index unchanged.
  It does not unstage a staged hunk. See |codediff-revert|.
- Rename keymaps.view.discard_hunk to keymaps.view.revert_hunk; there is no
  compatibility alias. The native default is <leader>hr. A personal mapping
  such as revert_hunk = "r" affects native tabs; popup r is fixed.
- Merge keymaps.conflict.discard/discard_all and conflict highlight names are
  separate settings; do not rename them as part of the hunk-key migration.
- Native gS/g?/t and explorer mappings do not govern ordinary status review.
  Use |codediff-popup-keys| rather than an old full-tab shortcut guide. Merge
  panes instead use ordinary editing and the controls in |codediff-merge|.
- Remove diff.conflict_ours_position, diff.conflict_result_position,
  diff.conflict_result_height, and diff.conflict_result_width_ratio. Merge
  roles/layout are fixed; Both has an explicit order, Use Base resolves, and
  Reset deliberately leaves the block unresolved.
- The old draft-handoff integration and its o mapping are removed.
- Do not expect global s/Ctrl-s to save. s stages/unstages in ordinary review
  and popup trees, but edits normally in merge Result. Workspace Ctrl-s opens
  review help; message Ctrl-s submits the dialog. Use :write in merge Result.
- Neovim 0.7 is not a valid runtime requirement for this fork's current popup,
  repository actions, and Revert implementation; see |codediff-requirements|.
